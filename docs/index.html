How AgentMachinist works · 2 minutes

An issue goes in. A reviewed PR comes out.

AgentMachinist runs the plan-and-build loop on your machine — but it cannot spend a keystroke of authority you didn't grant. You approve the exact plan. You merge the result. Everything between is machine work behind a test gate.

The loop

Six stations. Two gates are yours.

Scroll the story on the left; the board on the right tracks where the part is — and who is holding it.

STATION 01 · YOU

File one outcome, not a project.

A clear title, acceptance criteria, and the agent-task label. “Add CSV export for filtered rows” is a first run. “Improve reporting” is not. The label is the only trigger — nothing touches unlabeled issues.

GitHub · add label agent-task
STATION 02 · MACHINE

A plan you can read, before any code.

The harness reads your repository in its strongest read-only mode and writes a specification — summary, approach, testing plan, out of scope. The controller (never the harness) commits it, pushes agent/issue-42, and opens a draft PR that contains only the plan.

machinist watch --once
STATION 03 · YOU — GATE 1

Approval names one exact commit.

You read the spec, then approve. That binds your consent to the 40-character head SHA you actually reviewed. If anyone edits the branch afterward, the approval goes stale and execution refuses. Want changes? spec 42 --revise regenerates; --abandon rejects.

machinist approve --pr 18
STATION 04 · MACHINE

Built in a worktree, not your checkout.

Implementation starts fresh from the approved head in an isolated workspace. The harness edits files; the controller keeps Git custody, strips GitHub credentials from the harness environment, and afterwards checks for harness commits, remote pushes, and .machinist/ edits.

machinist run 42
STATION 05 · MACHINE

The test gate is authoritative.

The controller runs your configured tests itself — the harness may pre-run them to iterate, but its word is never trusted. A required failure blocks readiness, keeps the workspace as evidence, and pushes nothing. Deleting a test file is refused outright.

uv run pytest
STATION 06 · YOU — GATE 2

Ready means reviewable — never merged.

The controller pushes with a lease against the approved SHA and flips the PR from draft to ready. You review the diff against the spec and click merge yourself. AgentMachinist has no merge authority — the last word is structurally yours.

When something stops

Failures park. Nothing retries behind your back.

Approval goes stale

The spec branch changed after you approved. That is a safety stop, not a bug — read the new diff, then approve the current head.

machinist approve --pr 18

The test gate fails

Nothing is pushed. The workspace is kept as evidence — inspect it, then resume those edits or start fresh from the approved head.

machinist retry 42 --phase execute --run

You need it to stop

Cancellation cooperatively stops the running task and durably blocks re-dispatch. Pause the whole queue while traveling.

machinist cancel 42 --reason "…"

The full symptom table lives in the field guide and the operator runbook.

terminal / your first run

# install the controller

$ uv tool install agentmachinist

 

# in your repository — answer init's short setup questions

$ machinist init

$ machinist doctor

 

# review the generated files, then make setup durable

$ git add machinist.yaml .machinist/specs/.gitkeep .gitignore

$ git add -p .github/workflows

$ git commit -m "chore: configure AgentMachinist" && git push

 

# label issue 42 'agent-task', then run the loop

$ machinist watch --once # spec → draft PR

$ machinist approve --issue 42

$ machinist run 42 # build + test gate → ready PR
