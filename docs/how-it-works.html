How AgentMachinist works

You describe a Task and make two decisions. AgentMachinist runs the coding Harness, checks its work, and makes every commit.

Your two decisions

Approval and integration stay with you

Approval names one exact Spec commit. If the Spec changes, you approve the new commit before anything runs.

Integration moves your branch to the reviewed candidate by fast-forward only. A dirty checkout or a moved base stops it.

Custody

AgentMachinist makes every commit

  • The Harness drafts, edits, and reviews. AgentMachinist commits.
  • After each Harness run, AgentMachinist checks HEAD, local refs, and protected Git metadata for changes.
  • Required verification gates must pass before AgentMachinist commits a candidate.
  • This is detection plus reduced credentials, not a sandbox.

When plans change

Amend, retry, or publish

  • machinist amend turns feedback on a reviewed candidate into a new Spec, which needs a fresh Approval.
  • Local machinist retry defaults to resuming validated retained Execute edits. Add --fresh to start in a new Workshop.
  • machinist publish pushes the candidate and opens a GitHub PR or GitLab MR without rerunning any Phase.

Unreleased source checkout: optional bounded repair defaults off and can repeat implementation once after an eligible required Gate failure, before rerunning all Gates. It stays inside Execute and the approved Spec. Failed or interrupted repair needs explicit retry --fresh. This is not included in published 0.17.1.
